# traviz

traviz is a Next.js 16 app for marking countries on a Mapbox globe as visited, want to go, or not interested. Each Clerk user's marks are stored in a Turso (libSQL) database. Read this file before you change anything. `CLAUDE.md` is a symlink to it.

## How the app works

- Routes: `/` (globe), `/list`, `/stats` (the account and reset controls are at `/stats#account`), `/sign-in` and `/sign-in/verify`. `src/proxy.ts` sends signed-out users to `/sign-in` and signed-in users away from it.
- Signed-in pages go under `src/app/(app)/`, whose layout renders the globe shell. `src/proxy.ts` redirects every signed-out request except `/sign-in*`, so a new public page also needs a change there. The nav tabs come from `src/features/app-shell/navigation.ts`. A new route needs a function in `paths.ts`, an entry in the routes list above, and a nav entry if it is a tab.
- Sign-in uses Clerk email links only. There are no passwords and no social providers. The form is custom code in `src/features/auth`. The root layout sets `prefetchUI={false}`, so Clerk's prebuilt UI bundle never loads.
- Marks are a `Marks` record from `src/features/marks/colors.ts`, keyed by country code. `src/features/marks/marks-store.ts` is an optimistic zustand store. It updates the screen first, then calls a Server Action. Writes for one country run in order. Edits made before the first server snapshot are replayed on top of it. The `persist` middleware caches marks in localStorage under `traviz-marks`, so a repeat visit shows them at once.
- The store calls the actions in `src/features/marks/actions` as plain async functions, such as `setMarkAction(code, state)`. They are not form actions. The app has no `useActionState` and no form library. Each action calls `requireUserId` from `@/features/auth/server`, parses its input with the zod schemas in `src/features/marks/schemas.ts`, and writes through `src/features/marks/services/marks.ts`.
- The server snapshot loads in `SessionLayer`. `MarksProvider` reads it with `loadMarks`, and `HydrateMarks` passes it to the store.
- The globe is imperative. `MapCanvas` imports `mapbox-gl` on the client, and `src/features/globe/mount-globe.ts` creates the map. `map-spin.ts`, `map-country-events.ts` and `map-store-sync.ts` beside it bind spin, country events and store sync. React never renders map content. The globe stays mounted on all three app routes and only spins on `/`.
- `next.config.ts` turns on Cache Components and Partial Prefetching. Read request data, such as the session or marks, inside a `<Suspense>` boundary, as `src/app/(app)/layout.tsx` does for `SessionLayer`. Read the matching guide in `node_modules/next/dist/docs/` before you change caching or prefetching.
- Server-only code is `@/shared/server/database` (the Turso client), `@/shared/server/env`, `@/features/auth/server`, `@/features/marks/server`, `@/features/marks/services/marks` and `@/features/marks/schemas`. Each one imports `server-only`, so importing it from client code fails the build.

## Rules

Some older code still breaks these rules, with comments, PascalCase file names and a `../` import in `scripts/migrate.ts`. Do not copy it. The table at the end says which rules a tool checks today.

- Use bun for every package and script command. Never use npm, pnpm or yarn.
- Import with the `@/` alias, never `../` or `./`. CSS imports and packages are the exception. `@/paths` resolves to `paths.ts` at the repo root, and `@/*` resolves to `src/*`.
- Build every route path with a function from `paths.ts`, such as `export const listPath = (): string => "/list";`. Never write a route string inline.
- Use `cn` from `@/shared/cn` for conditional class names.
- Never use a type assertion (`as`) outside `paths.ts`. Never use a non-null assertion (`!`) or `any`. `as const` is fine. Fix the type with narrowing, generics or `satisfies`. Parse an untyped value, such as a `JSON.parse` result, before you use it. Never use `@ts-ignore`, `@ts-expect-error` or `@ts-nocheck`.
- Type the parameter of a `.catch` handler as `unknown`, as in `.catch((error: unknown) => ...)`, and narrow it with `instanceof`. Never type it as `Partial<Error>` or `any`. A helper that takes the caught value names its parameter `cause: unknown`, the name `anti-slop/no-unknown-parameters` exempts.
- Make every data change through a Server Action. Each action lives in `src/features/<name>/actions`, with one verb per file and `"use server"` at the top. Never use a route handler or a client `fetch` for a mutation.
- Each action checks the user with `requireUserId`, validates its input with zod, and only changes rows the user owns.
- Never put `"use server"` on a services or lib module. It turns every export into a public endpoint. Keep the modules that import `server-only` out of client code.
- The marks actions must not call `revalidatePath` or `refresh`. That would rerun `HydrateMarks`, drop pending writes and load an older snapshot.
- Put one React component in each file. Name the file after it in kebab-case (`src/features/country-list/country-row.tsx` exports `CountryRow`).
- Model each business operation once (single write path). Prefer one configurable component over near-copies, once a third copy appears.
- Write no comments. Use descriptive names instead of one-letter names, and use `T` for a single generic.
- Put tests next to the code they test, as `*.test.ts` or `*.test.tsx` under `src`, and run them with `bun run test`. `bun run test` only runs tests under `src`, so tests for `scripts` go in `src/shared/testing`. Tests can import modules that import `server-only`, because `bunfig.toml` preloads a stub for it. Run `bun run test:rules` after you change a rule in `tools/oxlint`. Bun's test runner cannot run those rule tests.
- Do not mock modules in tests. Pass dependencies in as arguments.
- Use Bun APIs only in tests, `src/shared/testing` and `scripts`. The app runs on Node in production.
- Keep each route's gzipped first-load JS within its entry in `bundle-budget.json`, plus 1% or 1 KB, whichever is larger. When a change needs more, run `bun run check`, then `bun run check:bundle --write`, and commit the new numbers, so the growth shows in the diff. Never preload JS in a route's HTML that the route does not load at first, such as the lazy `mapbox-gl` chunk. The check reads only the prerendered static shell, so it cannot see a preload inside a `<Suspense>` boundary that renders at request time.
- After a UI change, open every affected page in the dev server and screenshot it at 375, 768 and 1440 px. Fix layout breakage, overlap, clipped text and low contrast, then screenshot again. If you cannot run the dev server, say so instead of skipping this.
- Never loosen a check: no `continue-on-error`, no lint rule at `warn`, no higher `maxCrap`, no weaker react-doctor `blocking`, no inline `oxlint-disable` or `eslint-disable`. A lint rule may be off only in a file-scoped override listed in `lint-exemptions.json`, with the reason and when to remove it. A new entry needs a reviewer's sign-off. `gates.json` holds a copy of the CI workflow, `tsconfig.json`, `.oxlintrc.json`, `.fallowrc.json`, `doctor.config.json`, `.oxfmtrc.json`, `bunfig.toml`, the gate scripts and `devEngines`, and `bun run check:gates` fails when they differ, so a change that tightens a gate also updates `gates.json`.
- Before you report a task as done, run `bun run format`, then `bun run check`, and fix what they report.
